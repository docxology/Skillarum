## Findings

### CRITICAL-1: Non-hermetic `research validate` default reads real output/ from test (AGENTS.md violation)

- Evidence: tests/test_scholarship.py:636-646 invokes `research validate` omitting `--figures`; the CLI default `--figures` is `Path("output/figures/figure_registry.json")` relative to CWD (src/skillarum/cli.py:368), so `validate_figure_registry` reads this checkout's real registry.
- The real registry (output/figures/figure_registry.json, gitignored disposable output) has a stale `artifact_sha256` for `pipeline-trust-boundaries.svg`: stored a52fbc59... vs actual text hash ed631a60... (src/skillarum/figures.py:1419-1421 flags "artifact hash mismatch"), so the CLI exits 1 and the test asserts `== 0` -> fail.
- This violates the repo's own AGENTS.md:32-37: "Tests must be hermetic from a clean checkout: output/ is disposable and ignored, so a test may not read pre-existing generated skills or figures."
- The test's own comment at tests/test_scholarship.py:633-639 documents the identical root cause fixed earlier for `--publication` ("non-hermetic-default root cause") but missed `--figures`.

### CRITICAL-2: Stale disposable figure registry (hash drift in gitignored output)

- output/figures/figure_registry.json (gitignored) records an `artifact_sha256` for pipeline-trust-boundaries.svg that no longer matches the on-disk SVG. Verified: 1 of 10 figures hash-mismatched; the other 9 match.
- Impact: any command using the repo-relative `research validate` default reports a failed ledger from stale disposable state with no regeneration hint. State drift, not code drift.
- Fix applied: regenerated the registry via the canonical CLI so stored hashes match artifacts again (see Fixes).

### MAJOR-1: Test-order coupling between the two scholarship tests

- The two scholarship tests share real-output reads through relative CLI defaults, making suite results depend on execution order and prior local state. Same root cause as CRITICAL-1 (non-hermetic defaults), fixed together.

### MINOR-1: No regeneration hint on stale-artifact validation

- src/skillarum/figures.py:1422 emits only `"{figure_id}: artifact hash mismatch"` with no pointer to the canonical regeneration path (`skillarum figures --evaluation ...`). Left as-is (behavioral change out of lane scope; recorded for backlog).
